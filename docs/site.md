## Files

| Path | What it is |
| --- | --- |
| `site/index.html` | The landing page. Markup, both languages, and an inline script for preferences, tabs, the picker, the command transcripts and the star count |
| `site/send-to-kindle/index.html` | The Kindle guide, a single-column document on the same system |
| `site/style.css` | The one stylesheet for both pages: the Hallmark stamp, tokens, components, motion, breakpoints |
| `site/site.js` | Behaviour shared by both pages: scroll reveals, gliding highlights, Chinese word breaks, the theme and language cross-fade |
| `site/tui-demo.js` | The `zlib tui` recording on the landing page |
| `site/zh/` | Generated by `scripts/build-zh.mjs`, gitignored. Never edit it |
| `scripts/build-zh.mjs` | Writes `site/zh/` and `site/zh/send-to-kindle/` with the English removed |
| `scripts/check-site-text.mjs` | The browser check for runts, split words, forced breaks and overflow |

There is no build step for the English pages and no dependency besides the
Google Fonts stylesheet. `.github/workflows/pages.yml` runs `build-zh.mjs`
and publishes `site/`.

## Design decisions

### Direction

The site was redesigned with [Hallmark](https://github.com/Nutlope/hallmark)
(`/hallmark redesign`, full depth, brand kept) and then refined toward an
Apple-like restraint: say what zlib does and the command that does it,
nothing more. The first lines of `style.css` are Hallmark's stamp. They
record the shape (Workbench), the genre (modern-minimal), the hero, nav and
footer patterns, the signature element, every waiver with its reason, and
every reworded line. Keep the stamp current: a new exception gets a
`waive` line, and no more than three waivers stay in force (now 77, 79, 47b).

| Decision | Choice | Why |
| --- | --- | --- |
| Palette | Catppuccin Latte (light) and Mocha (dark) | The CLI ships both as `catppuccin-latte` and `catppuccin-mocha`, so the site and the tool match |
| Type | Literata for display and body, JetBrains Mono for code | Literata is an ebook face, right for a book tool; one family keeps the page quiet |
| Terminal type | SF Mono where the Mac has it, JetBrains Mono elsewhere (`--font-term`) | Transcripts look like the terminal they come from |
| Accent | Mauve (`#8839ef` / `#cba6f7`), one filled button recipe (`.btn.pri`) | Everything else that looks selected is a tab or toggle state |
| Signature | A playable replica of the `zlib search` picker in the hero | It shows the product instead of describing it |
| Transcripts | macOS Terminal windows (`.win`): 28px bar, traffic lights, no title | zlib runs in a terminal; the owner asked for authentic windows without the `you — zlib search` title |
| Prompts | `❯` on the landing page, `$` in the guide | The landing page shows a modern shell; the guide shows copyable POSIX commands |
| Languages | English and Chinese in one page, plus generated `/zh/` URLs | One source per page; each language still has its own URL for search engines |
| Star CTA | "Star on GitHub" in the nav and above the closing buttons, in both languages | Visible but limited to those two places |

### Page structure

The landing page runs: hero (picker) → install → `zlib tui` (recording) →
commands (list and transcript) → agents (plugin and MCP) → access
(`zlib doctor`) → themes → close (download again) → footer. Split sections
put text on five columns and the visual on seven.

The guide is one centred 76ch column: hero, setup steps, limits table, send
on download, FAQ ("Common problems"), close. It closes inside its own column
(waiver 77).

### Content sources

Copy is never invented. Each piece has a source to check when it changes:

| Content | Source |
| --- | --- |
| Picker columns, card, keys, help line | `internal/cli/book_feed_view.go` (`bookColumnWidths`, `selectedBookCardWithCover`, the help strings), `book_cover.go` (`coverWidth`, `coverRows`), `search_interactive.go` |
| Picker covers | Open Library edition covers in `site/covers/`, one per sample book, named by book ID; editions and sources in `site/covers/README.md` |
| `SCREENS` (login, profile, config, doctor, recommended) | The CLI's own views, captured with a temporary Go test on sample data and converted from ANSI |
| `tui-demo.js` frames | The shell's `View()` at 80x24, driven by real key presses through `shellStep` |
| Transcripts and `update` line | Strings the CLI prints (`internal/cli`) |
| Plugin and MCP commands | `README.md`, `docs/mcp.md` |
| Theme swatches | The CLI's built-in themes |
| JSON-LD | `README.md` and `go.mod` (platforms, Go version) |

Book listings and `doctor` output are sample data. Counts that drift (themes,
domains) stay out of the copy.

- **The tui recording** has eleven frames in catppuccin-mocha: home, `/`,
  down, down, `s`, `e`, Enter, then `dune` typed into the search form.
  Regenerate them when the home screen, the command dialog or the search
  form change. The markup carries the home frame for visitors without
  script, and the key list beside it highlights the step on screen.
- **The Commands list** covers the everyday commands in three groups (find,
  get, set up); `weread` sits beside `kindle` under "get". `most-popular` and `favorites` ride on the `recommended` row;
  `tui` and `mcp` have their own sections. A command that opens a page in a
  terminal (`recommended`, `profile`, `config`, `doctor`) shows that page
  with no prompt, `login` shows its inline form under the prompt (doctor at
  56 columns, the rest at 80), and the rest show a prompt and plain output.
  The `update` line is the "is up to date" message with the version being prepared.
- **`og.png`** (1200x630) is a screenshot of a small standalone HTML card;
  regenerate it by rendering that card again. `og:image` and
  `twitter:image` point at it by absolute URL, as scrapers require.
- **JSON-LD** (`SoftwareApplication`) is checked field by field against the
  README and `go.mod`; update it when platforms or the Go version change.

## UI and UX guidelines

**Copy.** A headline, one line, the command. If a sentence only explains,
it belongs in `docs/`. Describe what the user can do and how; keep commands
and flags exactly as the CLI accepts them. Chinese copy follows Chinese
product-site conventions (natural, concise, no translationese), keeps
technical terms and commands in English, and puts a space between Han and
Latin text.

**Tokens only.** Every colour, font, size, space, radius, duration and
easing goes through a `:root` token. Spacing stays on the 4px scale
(`--space-*`); a one-off 14px fails Hallmark. Use `--color-*` on the page and
`--t-*` inside terminal windows.

**Contrast.** Body text meets 4.5:1 on its surface in both themes. In Latte
the terminal colours are the CLI's hues darkened until they pass 4.5:1 on
the lightest surface they sit on; the page palette itself is unchanged.

**Controls.** Controls are at least `--control` (44px, 40px under 24rem)
tall. Tabs use `role="tablist"` and `aria-selected`; the language buttons use
`aria-pressed`; icon buttons carry an `aria-label` that names the action
("Switch to light theme"). Focus is a 2px `--color-focus` outline. Presses
scale to 0.97.

**Terminal windows.** Every transcript sits in a `.win`. Notes on how to go
further go under the window in `.win-caption`, never inside it. A single
command meant for copying is a plain code block with a copy button, not a
window. Drawn screens (`.screen`) size their type to the window with
container units and stay centred.

**Platform.** Windows visitors get the winget command in the hero and the
install switcher, with a `>` prompt; everyone else gets Homebrew.

**Works without script.** Nothing is hidden until `site.js` sets
`.js-reveal`. Without script every section shows, selected items keep their
own background, the tui section shows its home frame, and Chinese wraps by
the browser's rules. Print never waits for a reveal.

**Preferences.** Theme and language are saved in `localStorage`
(`zlib.theme`, `zlib.lang`) and applied by a small script in `<head>` before
first paint, so a Chinese reader never sees English first. Defaults follow
`prefers-color-scheme` and `navigator.language`. Every `localStorage` access
is wrapped in `try`.

## Text layout

A line breaks only where it has to. Where it breaks, it breaks between whole
sentences, then between words, never inside a word, and no line holds one or
two words alone when the space was there.

### Rules

1. **No `ch` caps on short text.** A lead, heading, caption or note takes
   its column's width. Cap only a column of running prose, and cap the
   column (`.doc { max-width: 76ch }`), not the element.
2. **Wrap by shape.** Headings and one-sentence text (`.lead`, a sentence in
   `.ln`, `.win-caption`, `.note`, `summary`, `.keys li`, table values, a
   guide paragraph without `.ln`) use `text-wrap: balance`. A paragraph of
   several sentences uses `pretty` on desktop, where balance would halve it,
   and `balance` at 40rem and below, where it runs to three or more near-full
   lines and `pretty` would still leave two words. Neither adds a line.
3. **Mark sentences.** In a lead and in any paragraph of two or more
   sentences, wrap each sentence in `<span class="ln">` (inline-block). It
   follows the previous sentence when it fits and starts its own line when it
   does not. Keep a question with its answer in one span. Outside leads the
   spans flow inline at 40rem and below. In a lead, leave a sentence longer
   than about 50 characters (28 in Chinese) unwrapped: as a block it would
   force a line of its own.
4. **Chinese breaks between words.** `site.js` finds word boundaries with
   `Intl.Segmenter`, marks them with `<wbr>` and sets `.zh-words`, under which
   `[data-i18n="zh"]` gets `word-break: keep-all`. A one-character word stays
   with the word before it or, opening a phrase (会 after a comma, 给 before a
   command), with the word after it. Never set `keep-all` without the marks:
   an unmarked Han run cannot wrap and overflows.
5. **Units stay whole.** Hyphenated names (`Z-Library`, `E-mail`) go in
   `<span class="nowrap">`, because Literata has no non-breaking hyphen.
   Numbers join their units with `&nbsp;` (`25&nbsp;MB`). Inline `code` never
   breaks.
6. **Tables.** The label column is `width: 1%; white-space: nowrap`, so it
   takes its text's width and the values get the rest.
7. **Copy.** Do not end a sentence on a short word after a long unbreakable
   command; put the command first or last. Reword rather than force breaks
   with `<br>`.
8. **Never trade wrapping for overflow.** Commands and code blocks wrap
   (`pre-wrap`, `overflow-wrap: anywhere`). Only the drawn grids inside
   terminal windows scroll.

## Responsive layout

| Breakpoint | What changes |
| --- | --- |
| ≤ 72rem | Every split section stacks: hero, install, tui, commands, access, close. A text column narrower than about 420px folds a lead into three or four lines |
| ≤ 60rem | Gutter 24px, smaller section gaps, nav links hidden, swatches in two columns, footer in three |
| ≤ 40rem | Gutter 16px. Sentence spans flow inline and guide paragraphs balance. The command list becomes wrapped chips with only the command showing. The guide's step markers and FAQ answers give their indents back to the text. Swatches in one column, the star button loses its label |
| ≤ 24rem | Controls 40px, tighter nav and terminal padding |

All split sections stack at the same breakpoint. Test widths: 320, 360, 375,
390, 414, 480, 600, 768, 834, 1024, 1180, 1280, 1366, 1440, 1600 and 1920px.
The page never scrolls sideways (`overflow-x: clip` on the page cuts anything
that tries, which is why overflow is a defect, not a scroll).

## Motion

Subtle, quick, and the same language everywhere, after openbot.run.

### Tokens

| Token | Value | Used for |
| --- | --- | --- |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` (ease-out-quint) | Things that arrive: load, reveals |
| `--ease-glide` | `cubic-bezier(0.32, 0.72, 0, 1)` (iOS sheet) | Things that move between places: highlights |
| `--ease-fold` | `cubic-bezier(0.4, 0, 0.2, 1)` (even in-out) | Heights that open and fold: FAQ answers |
| `--dur-micro` / `--dur-short` | 120 / 160ms | Opacity of highlights, small feedback |
| `--dur-swap` | 240ms | Pane and transcript swaps, the nav's entrance |
| `--dur-fold` | 280ms | FAQ answers and their `+` |
| `--dur-glide` | 460ms | Gliding highlights |
| `--dur-enter` / `--dur-reveal` | 500 / 720ms | Load and scroll arrivals |
| `--enter-step` / `--reveal-step` | 40 / 80ms (footer 120ms) | Stagger between items |

### Where motion happens

- **Load.** The nav and the hero lines settle 40ms apart, rising from a small
  blur (text is painted from the first frame, only sharper after). The
  picker draws top to bottom the way the TUI paints a frame, and its key hint
  fades in only after the draw ends (`--draw-delay + --draw-dur`).
- **Scroll.** A `[data-reveal]` group arrives once; its visible `[data-r]`
  items follow 80ms apart. `site.js` counts items at reveal time and marks the
  group `done` after 2s, so later tab switches inside it use the short swap.
- **Use.** Panes and transcripts swap with a 240ms blurred fade. One
  highlight glides under the hovered nav link, the selected tab and the
  selected command. FAQ answers open by height with their text fading. Theme
  and language cross-fade through a view transition (0.32s).
- **The tui recording** plays only while in view and holds the home screen
  with reduced motion.

### Standards

1. **Animate `transform` and `opacity`.** Highlights use FLIP: take the new
   size at once, then slide and scale back from the old box with transform
   only, so nothing is laid out on each frame.
2. **When height must animate** (a disclosure), animate
   `::details-content` `block-size` with `interpolate-size: allow-keywords`,
   use `--ease-fold`, keep the inner spacing as padding (a margin collapses
   out of the clipped box and jumps at the end), and add `contain: layout`.
3. **No crawling tails.** A curve that covers 90% of the distance in the
   first third reads as lag on the rest. Arrivals may ease out; anything
   the user waits on (a fold, a swap) finishes within 300ms.
4. **One property, one timing.** Parts of one change (an answer's height,
   its text, its `+`) share a duration and curve.
5. **Reduced motion.** Nothing travels, blurs or glides; the fades that
   confirm a change stay (0.2 to 0.3s). Every new animation needs its entry in
   the `prefers-reduced-motion` block.
6. **Measure, don't guess.** Check frame times and per-frame positions with
   CPU throttling (see [Verifying a change](#verifying-a-change)). A smooth
   frame rate with a jump in positions is still a defect.

## Implementation patterns

**Bilingual pairs.** Every string is a sibling pair of
`data-i18n="en"` / `data-i18n="zh"` elements; CSS shows the one matching
`<html data-lang>`. Script-written text (command notes) writes both. A new
language is a third value. `build-zh.mjs` strips the English, rewrites head
tags, links and JSON-LD, and relies on the `<html>` tag and the
`setLang(...)` call keeping their form; a new page needs an entry in its
`PAGES` list. Run it after every edit.

**Reveals.** Put `data-reveal` on a group and `data-r` on its items. Never
hide content in CSS without the `.js-reveal` gate.

**Tabs.** Buttons carry `data-inst`, `data-agent` or `data-cmd` with
`aria-selected`; panes carry `data-pane` / `data-agent-pane` and the class
`on`. `site.js` adds the glide to any `.tabs` or `.cmd-list` and follows
`aria-selected` with a `MutationObserver` and sizes with a
`ResizeObserver` (labels change width with the language).

**Copy buttons.** `data-copy="…"` holds the exact command; the button shows
a done state for 1.4s.

**Terminal content.** `.win > .win-bar + .win-body`. Captured screens are
HTML built from ANSI: SGR state carries from code to code, colours map to
terminal classes so they follow the site theme, and box and block glyphs
(`╭─╮│╰╯█`) become `.bx` cells because the web font lacks them. Each screen
sets `--cols` and scales its type with
`min(1em, calc((100cqi - 2 * var(--space-md)) / (var(--cols) * 0.6 + 0.2)))`.

**The picker.** Columns follow `bookColumnWidths` for the window's measured
width, with one cell of slack, and are laid out again on resize and when the
web font arrives (`fonts.ready` and `loadingdone`). Under 70 columns it
switches to the short help line, like the TUI.

**Star count.** Fetched from GitHub's public API and cached in
`localStorage` (`zlib.stars`) for an hour; on failure the button shows no
number, or the last one seen.

**Chinese word breaks.** In `site.js`, scoped to `[data-i18n="zh"]`, skipping
`code`, `kbd`, `pre`, `.win`, `.nowrap` and anything already `nowrap`; a
`MutationObserver` marks text added later. Inserted `<wbr>` elements do not
copy with selected text.

## Issues and solutions

Each problem found so far, why it happened and what now prevents it.

| Symptom | Cause | Fix and guard |
| --- | --- | --- |
| Headings, a lead and a button cut off on phones | `word-break: keep-all` on Chinese headings made each Han run unbreakable; the column grew and `overflow-x: clip` cut it | Removed; `keep-all` now only with `<wbr>` marks. The check reports overflow |
| "Search, download, and send books to / Kindle." | `ch` caps on short text | Caps removed; only the guide's column has a measure (rule 1) |
| Leads folded into four lines between 960 and 1152px | 5fr split columns of 330 to 400px | All splits stack at 72rem |
| One or two words alone on a last line (68 found) | Default wrapping; two sentences flowing as one | `balance` / `pretty` by shape, `.ln` sentence spans (rules 2, 3) |
| "Z-\|Library" | `balance` broke at the hyphen | `.nowrap` span; the check reports split words |
| "Message / size", "扩/展/名" | Auto-sized label column shrank beside a long value | `width: 1%; white-space: nowrap` on the label column |
| Guide hero 736px in English, 749px in Chinese | A grid item with auto margins shrink-wraps | `.doc { width: 100% }` |
| FAQ answers broke mid-sentence into half-width lines | `balance` on multi-sentence paragraphs | `pretty` plus `.ln` on desktop, `balance` only at 40rem and below |
| "亚马/逊", "邮/件", "支/持" (19 found) | Browsers may break between any two Han characters | `Intl.Segmenter` + `<wbr>` + `keep-all`; the check segments Chinese and reports a split word |
| "文件 / 大小" after the word-break fix | Chrome breaks at `<wbr>` even under `white-space: nowrap` | `site.js` skips `nowrap` text; the check reports forced breaks |
| "The 25 / MB check" | A normal space between number and unit | `&nbsp;` |
| "“已 / 认可", "给 / `zlib mcp`" | A one-character word stranded after punctuation | It joins the following word, and the space after it becomes non-breaking |
| FAQ fold felt laggy and jumped 16 to 21px at the ends | The answer's bottom margin collapsed out of the animated box; the 460ms sheet curve crept for 300ms | Padding instead of margin, `--ease-fold` over 280ms, text fades with it, `contain: layout` |
| Picker key hint shown before the window finished drawing | The caption had no delay | It fades in after `--draw-delay + --draw-dur` |
| The tui home screen sat off-centre | Fixed type size in a variable window | `.screen` sizes its type from the window width and its column count |
| Picker columns a cell wide after load | The first layout measured the fallback font | Re-layout on font load, one cell of slack |
| Highlight lagged a language switch | Labels change width with the language | `ResizeObserver` on the box and its children |
| Content hidden without script, or in print | Reveal styles applied unconditionally | `.js-reveal` gate and a print rule |
| Phone text squeezed by indents | 56px step markers, 24px answer indents on a 288px line | Indents dropped at 40rem, spacing kept on the 4px scale |

Testing pitfalls found on the way:

- Headless Chrome reports a zh-CN locale and the host platform: set
  `zlib.lang` in `localStorage` and stub `navigator.platform` to test a given
  language or the Homebrew default.
- Headless clipboard writes fail; the copy-button checks need a headed
  browser.
- Intercept `api.github.com` so the star count is stable and the rate limit
  is untouched.
- Hallmark's static pass renders through `file://`, which cannot load
  `/style.css`; read its pixel findings from the `--url` pass.
- A check script that scans text must skip `.win` (fixed grids) and
  screen-reader-only text (absolutely placed with a `clip-path`).

## Verifying a change

```bash
node scripts/build-zh.mjs
python -m http.server 8000 --directory site      # another terminal
PUPPETEER_CORE=/path/to/node_modules/puppeteer-core CHROME="/path/to/chrome" \
  node scripts/check-site-text.mjs                # must print nothing found
```

`check-site-text.mjs` loads both pages in both languages at the 16 widths,
opens every tab, command row and FAQ answer, and exits 1 on a runt, a split
word (Chinese words as `Intl.Segmenter` finds them), a `nowrap` element that
wraps, or overflow. `puppeteer-core` is not a dependency of this repository:
install it in a scratch folder and point `PUPPETEER_CORE` at it.

Then, by kind of change:

| Change | Also do |
| --- | --- |
| Any | Look at the changed blocks at 375, 768 and 1440px in English and Chinese: the check cannot see a paragraph that is merely half as wide as it could be |
| Styles or layout | Run Hallmark: `node <hallmark>/skills/hallmark/scripts/sloplint.mjs site/index.html site/style.css site/send-to-kindle/index.html --genre modern-minimal --url http://localhost:8000/ --url http://localhost:8000/send-to-kindle/`. No open FAIL, REFLEX or WARN |
| Motion | Record per-frame positions and frame times with 4x CPU throttling (CDP `Emulation.setCPUThrottlingRate`, `Performance.getMetrics`). Positions must change continuously and settle without a final jump. Check with `prefers-reduced-motion: reduce` too |
| Script | Load the page with script disabled: every section shows, nothing is stuck hidden. No console errors |
| Copy | Check commands and output against the source in [Content sources](#content-sources); update both languages |
| CLI output, screens or the tui | Regenerate the captures from the CLI; never hand-edit a screen |

`site/` is outside `make check`; `.github/CONTRIBUTING.md` lists these steps
for commits.
