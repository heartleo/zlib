# zlib TUI changes

Keep interactive CLI and shell entry points on shared models. `profile` uses
`profilePageModel`; Kindle uses `runStandaloneShellCommand` for file selection,
configuration, confirmation, password setup, and send results. Standalone pages
exit to the terminal on return. Preserve JSON and non-interactive send behavior.
Check `TestStandaloneKindleSharesShellPages`, `TestStandaloneKindlePasswordAndResult`,
and `TestStandaloneProfileMatchesShellPage` when changing these flows.

Home has no search input or Enter-to-search hint. Open commands with `/`;
ignore ordinary typing, paste, and Ctrl+K on idle home. Esc closes the command
list and restores home without an input. Keep the signed-out login shortcut.
Check `TestShellHomeRequiresSlashForCommands` when changing home input handling.

Use `renderActionButton` from `tui_layout.go` for every operation on a form,
dialog, or result page. Its idle state uses the theme surface and title color;
focus uses a filled accent, or error color for a destructive action. Keep two
cells of horizontal padding, no border, and no `>` prefix. Wrap action groups
with `actionButtonRows` at the available width. Color gaps between dialog
buttons with the panel background; plain spaces can expose the terminal color
after an ANSI reset. List and folder rows keep
`selectionRow`. Check `TestActionButtonsShareConfirmationStyle` after changing
button rendering.

For the theme picker, keep the list and filter in the current palette while the preview follows the highlighted name. Paint component backgrounds, including cursor and separator cells. Check `TestThemePickerColorsFollowSelection` for all palettes at compact and wide sizes; preview and cancellation must not write preferences.

Custom themes live in the user config `themes` directory. Ctrl+N copies the selected palette into a named file; Ctrl+E edits custom colors or starts a copy of a built-in. Validate names and `#RRGGBB` values before saving. Ctrl+S writes the file; Esc discards draft edits. Keep the selected-book preview row on the candidate theme's surface, with every preview cell painted. Check `TestCustomThemeCreateEditAndReload`, `TestCustomThemeValidationAndCancel`, and `TestThemeEditorFitsAndKeepsPaintedBackground`.

Compare against a local clone of [charmbracelet/crush](https://github.com/charmbracelet/crush) (`<crush-checkout>`). Check its current HEAD before relying on an old revision cited in docs. Browse `internal/ui/` for layout and component patterns. Its `internal` packages cannot be imported by zlib; use the Charm packages already in `go.mod`.

Read [the TUI layout rules](../../../docs/tui.md#book-list-spacing) before changing book lists or cards. `book_feed_view.go` renders the shared Search, Favorites, Recommended, Most popular, and History list; keep its row calculation and rendered height aligned at compact and expanded terminal sizes.

Search results appear together when a request finishes; do not bring back row-reveal animation. Loading, empty, and failed Search states keep controls at the bottom. Empty results show the page and filter action. Check `TestSearchResultsAppearTogetherAndSelectionStaysStable` and `TestSearchLoadingAndEmptyKeepControlsAtBottom`.

The Search form in `search_filter_form.go` shows query, year range, language, format, exact match, and sort order together. Long choices open a centered picker; arrows navigate and Space toggles multiple choices. Ctrl+S submits; invalid years keep the form open with the error directly below the field. Filter rows use a fixed label column under a `sectionHeader("Filters", …)` rule; do not pass aligned label text through `selectionRow`, which collapses spaces. The query box needs 20 rows; the form caps at 100 columns. The result page reopens the same form with current filters and must resize it through `tea.WindowSizeMsg` so the input width matches the terminal. Loading, result status, and empty states show `searchFilterChips`; the status line drops them when fewer than 12 cells remain. Check `TestSearchFilterFormAlignsLabelsAndShowsErrorsAtField`, `TestSearchFilterFormQueryBoxFollowsTerminalSize`, `TestSearchStatesShowActiveFilters`, and `TestSearchRefineSizesQueryToTerminal`. Keep `SearchOptions`, `searchEAPI`, direct `search` flags, and the form mapped to the same EAPI fields. Check `TestSearchFilterFormSelectsEveryEAPIConstraint` and `TestSearchEAPISendsAllFilters`.

Book details come from EAPI for the selected `id:hash`. Fetch after selection settles, cache by reference, and keep late results tied to their original book. Show fields the response provides; the Android model does not guarantee categories or separate ISBN fields. See [EAPI notes](../../../docs/eapi.md#current-scope) for the evidence boundary.

Check the shared layout and selection tests in `internal/cli/book_feed_view_test.go` and the EAPI mapping tests in `internal/zlib/eapi_book_test.go`. When changing shared layout code, run `go test ./...` and `go vet ./...` after the focused test passes. Update `docs/tui.md` when interaction or spacing rules change.

Keep recoverable failures on the page that owns the request. Download failure shows the book, a URL-safe reason, and `r` to retry with the same directory; retry must start a new shell generation so late messages are ignored. Kindle send failure shows the file and reason but has no automatic retry because SMTP delivery may have completed. Keep login and setting validation on their forms. Check `TestShellDownloadFailureKeepsContextAndRetries` and `TestShellKindleFailureRequiresExplicitResend` when changing these paths.

In the shell, a completed download stays on its page with the absolute saved path and Back. Show Send to Kindle only when the saved file extension is in kindleAllowedTypes; keep hidden actions unreachable by keyboard. The Kindle action confirms before SMTP; cancel, missing settings, success, and failure return to the saved-file page without restarting the download. Wrap and scroll long paths; keep the standalone CLI download exit behavior. Check `TestShellDownloadReturnsToSelectedBook`, `TestShellDownloadKindleActionReturnsToCompletion`, and `TestDownloadCompletePathWrapsAndWaitsForReturn`.

The Kindle and WeRead file pickers use `bookFileList`, which lists folders and only files whose extension (any case) the target accepts; do not return to the Bubbles file picker, which can only grey unsupported files out. Directory reads run in a command and reads for a folder already left are ignored. Check `TestWeReadFilePickerListsOnlySupportedBooks` and `TestWeReadFilePickerNavigatesFolders`.

The WeRead login QR code (`weread_qr.go`) keeps square modules: one column and half a row each, drawn with half blocks, on a panel with as many modules across as down (`qrSide`). `qrFit` picks the largest quiet zone from 4 down to 2 that fits the terminal; never draw a clipped code, name the size needed instead. Encode at level L. The page uses `tightScreenView`, which spends four rows on title, subtitle, status and key hints, so a standard 80×24 terminal shows the whole code. Check `TestQRPanelIsSquareWithQuietZone`, `TestQRFitPicksLargestQuietZoneThatFits`, `TestWeReadLoginShowsWholeCodeOnStandardTerminal` and `TestWeReadLoginNeverClipsTheCode`.

WeRead import checks format and per-format size with `weread.CheckImportFile` before any confirmation; the confirmation note names the size and target account. The import page lists the three `weread.ImportStage` steps with done, current and pending marks, and shows the bar only during upload. Esc cancels and stays on the page until WeRead answers the cancellation; Ctrl+C then stops waiting and reports the import as unconfirmed. Delivery outcomes on the saved-file page use `noticeSuccess` or `noticeError` through `returnToDownloadCompletion`. The settings account page keeps status, actions and key hints before the optional intro and import rules. Check `TestWeReadImportPageShowsEachStage`, `TestWeReadImportCancelWaitsForWeRead`, `TestShellWeReadImportResultNamesOutcome` and `TestSettingsWeReadAccountShowsImportRulesWhenTheyFit`.

Cancel returns to the saved file; a write error stays on the form. Check `TestShellKindlePasswordSaveFailureKeepsMaskedForm` and `TestSettingsSaveSMTPPasswordWithoutChangingOtherKeys`.

The Doctor shell page uses Bubbles list, spinner, and the shared help renderer, following the local Crush command-list pattern. Keep its results limited to domains accepted by `availableDomains`. Show one domain per row, use the accent border for the focused row, and mark the current configured domain separately. Retry and page exit must cancel the prior probe context. Check `TestDoctorPageListsOnlyAvailableDomains` and `TestDoctorPageRetryRejectsOldResultsAndCancelsOnExit` after changing it.

Check `TestProfileQuotaBarUsesWidthAndDoesNotRepeatRemaining` and `TestProfilePageUsesFullScreenAndScrolls`.

At 80×24, show five commands with descriptions below their names; narrow terminals use one-line rows. Render it on the title row (row 0), never on row 1, which holds the list status line. Keep it above the input and key hints, including while the command dialog is open. Keep actionable form and request errors on their owning page. Check `TestShellErrorNoticeStaysUntilKeyPressWithoutReplacingInputOrHelp`, `TestShellInfoAndSuccessNoticesExpire`, `TestShellNoticeKeepsListStatusVisible` and `TestShellThemeSavedNoticeLeavesFooterAvailable`.

The download-directory choice and folder browser use a centered dialog over the selected book list. The displayed directory is the default action; the browser reopens at the current selection. Keep both direct-command and shell entry points on the same model. Check TestDownloadDirectoryDialogKeepsBookListBehindIt and TestDownloadDirectoryDialogAcceptsTypedFolder.

The metadata page (`meta_tui.go`, glue in `shell_meta.go`) is one `metaPageModel` shared by `/meta` and interactive `zlib meta <file> --fetch`; keep it a single model, not a fork per entry point. It opens on the prepare step (`meta_prepare.go`, stage `metaPrepare`) and searches only on Enter, through a `metaRun` that copies of the page share, so repeated `Init` calls start nothing new, and each search creates a fresh run. The prepare page shows the file name's reading first, then what the file embeds, the merged terms with where each came from (`metasource.Extract` builds them, shared with `zlib meta --fetch`; `t` swaps in the other title through `Extraction.UseOtherTitle`), and the sources as `[x]`/`[ ]` rows on a draft copy that Enter commits. A title read from a name or a download record is `TitleGuessed` and cannot confirm a hint ISBN. Terms and sources come before the file's own lines so short terminals keep them. Ctrl+D (not `r`, which is retry on the no-match page) saves the sources that are on through `saveSources` (`withMetaSourceSaver(saveMetaSources)`, which writes `ZLIB_METADATA_SOURCES` through `settingsStore.save`, applies it to the process only when nothing overrides it, and returns the overriding setting's name for the message) and nothing is saved otherwise; `--source` sets `metaSourcesFlag` for one run (`applyMetaSourceFlag`, resolved by `configuredMetaSources`, flag > env > default; the saved value reaches the env through the `.env` load) and is never saved; `s` from the results returns to the prepare page, and Esc during a search returns to the page it started from (`remember`/`abandonSearch`; a prepare page opened from the results keeps them in `metaSnapshot.outer`, so Esc steps back one page at a time). Esc on the results or the no-match page goes back a step through `backToPrepare` (the prepare page with the terms and sources as searched, `m.prev` cleared so Esc there leaves and Enter searches again); it must not keep the results, or Esc would loop between the two pages, and a page built with no sources still leaves. `q` and Ctrl+C leave from the results. Check `TestMetaResultsEscGoesBackToThePreparePage`, `TestMetaResultsEscKeepsAnEditedSearchAndTheChosenSources`, `TestMetaNoMatchEscGoesBackAndQLeaves`, `TestMetaSourcesKeyStillReturnsToTheSameResults` and `TestMetaResultsEscLeavesWhenThereAreNoSourcesToChoose`. The fields page is a workbench (`meta_bench.go`): `benchRows` lists `metasource.EditableFields` the format can store (plus other identifiers the match proposes), each with the file's value, the match's and its `m.plan` index; `pending` resolves what is written, in this order: `m.extra` (typed with `Change{Field, Old}.Edit`, cleared with `metasource.Clear`, a chosen image with `ChangeFromCover`), then the plan row if `m.selected` (taking the match), else the file's value, which writes nothing. `apply` writes only rows whose origin is not the file, reusing a match cover from `coverCache`. `m` on the prepare page opens it with `manual` set (no match column, no lookup). Wide terminals get two `benchBox` panels side by side whose rows line up; each reserves its cover place through `coverBlock` (`leftCoverState`/`matchCoverState`: blank where the image is drawn, else a bordered `loading…`, `no cover` or `cover unavailable` label), and `coverNeededCmd` asks for the match's cover on every resize that makes the panels visible; narrow ones `benchTable`. The description edits in a `textarea` (`newMetaTextEditor`; Enter is a new line, Ctrl+S keeps). Esc with changes sets `confirmDiscard`. Descriptions are shown through `shownValue`/`metasource.PlainText` but compared and written raw. Covers: `coverSlots` (the `coverSlotter` interface in `cover_graphics.go`) gives the graphics layer one or two placements (several images per frame, each with its own Kitty id), none while an editor, the help or the question is open; prepare, results and details pages show a side cover and narrow their text with `sideNarrow`; standalone `zlib meta` runs under `runCoverProgram`. Check `TestBenchWritesOnlyWhatEachFieldDecides`, `TestBenchEditsWithoutALookup`, `TestBenchAsksBeforeDiscarding`, `TestBenchWritesTheMatchCoverItShowed`, `TestBenchLayoutsKeepSaveAndEsc` and `TestCoverOutputDrawsAndErasesEveryImage` when changing it. The review UI lives in `meta_review.go`: `metaSubtitle` puts the step (`metaStepInfo`) in the subtitle, shortening it to `n/3` when narrow; `candidatesBody` aligns columns with `padCell` (width-aware) and `candidateEffect` lists what a match would add (`DefaultSelected`), could add unselected, differs on, and cannot store (`canOffer` false), all from `metasource.Plan`, so it promises exactly what the next page selects; `?` (`openHelp`, `metaHelpRows`, a scrolling `helpView`) lists every key of the stage it was opened on, less those that do nothing there, and swallows other keys until closed, but is text while an editor is open; the file details are a `viewport` (`openInfo`, `resizeInfo`). Colour only repeats what the text says (`(replaces)` and friends stay). Check `TestMetaPageHelpListsEveryKeyOfThePageAndCloses`, `TestMetaResultsSayWhatAMatchWouldChange` and `TestMetaFileDetailsScroll`, `TestMetaPageHelpScrollsOnShortTerminals`, `TestMetaResultsNameFieldsTheFormatCannotStore` and `TestMetaResultsPageKeysMoveAPage` when changing it. The prepare page is a stack (`prepareBody`): the book detail card (`prepareCard`/`prepareCardLines`: title and authors, then labelled rows aligned to one value column, packed into dotted lines when the rows are too few, no padding lines inside the text; the shortcuts live in the `Search for` `sectionHeader`; the shape of `selectedBookCardWithCover`: rounded accent border, cover slot `coverWidth`×`coverRows` on the left when `prepareLayout` says there is room and `coverFits`, else text only), then `prepareTerms`, then `prepareSources`; `prepareLayout` hands rows out so the sources are never cut (full card with cover, short terms, a few text lines, a title line, no card), and `coverSlots` puts the cover at row 4, column 2, inside the border.
